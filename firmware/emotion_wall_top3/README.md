# 왼쪽 22개에 상위 3개 감정 그라데이션

새 스케치: firmware/emotion_wall_top3/emotion_wall_top3.ino
총 64개, 구간 22/21/21, GPIO18과 GRBW 설정 유지.
데이터 연결이 왼쪽 → 가운데 → 오른쪽 순서라는 기존 가정을 유지합니다.

- 1번 구간(인덱스 0~21): 양수 점수의 상위 3개 감정 대표색을 1→2→3→1로 이어 반복 이동.
- 상위 3색은 RGB 단순 평균 대신 HSV 색상환의 짧은 경로로 연결하고 채도를 유지합니다.
  중간색은 표시되며, 서로 비슷한 감정색이 상위권이면 색 구분이 약할 수 있습니다.
- 점수의 크기는 순위와 기존 속도 계산에 반영되며, 각 색의 그라데이션 공간은 동일하게 배분합니다.
- 유효 감정이 1~2개라면 남은 자리는 대표색을 반복합니다. 존재하지 않는 감정색을 만들지 않습니다.
- 왼쪽 이동 주기: 기존 감정 속도 주기×0.55, 범위 600~2400ms로 제한.
- 2·3번 구간은 기존 대표색 주변 그라데이션과 감정별 속도(900~6000ms)를 유지.
- 최대 밝기 96/255, LED당 채널합 160, W 혼합 없음. 왼쪽에는 별도 밝기 물결 없음.
- 색 팔레트는 2.6초 동안 부드럽게 바뀌며, 속도 전환 시 위상을 초기화하지 않습니다.
- API 요청이 끝나도 ESP32가 애니메이션을 계속 실행합니다.

## 적용

API 서버 Control+C → 새 스케치 업로드(115200) → Arduino 종료 → API 서버 재시작 → 웹에서 재분석.
새 TOP 명령은 이전 펌웨어에서 지원하지 않으므로 재업로드가 필요합니다.
실제 포트가 바뀌었다면 아래 명령을 수정하세요.

```sh
cd ~/emotion-wall
source .venv/bin/activate
EMOTION_WALL_PORT=/dev/cu.usbserial-5C3D1057711 python -m uvicorn api:app --host 127.0.0.1 --port 8000 --workers 1
```

## 통신과 API

`TOP,R1,G1,B1,R2,G2,B2,R3,G3,B3,이동시간ms\n`
응답은 `OK,TOP,...\r\n`. 아홉 채널 0~255, 각 RGB는 비소등, 주기 600~2400.
새 SerialSender.send_top3(colors, period_ms)가 확인 응답을 검사합니다.
TOP은 왼쪽에만 적용하며, API는 이후 ROW,2 및 ROW,3 명령으로 나머지를 업데이트합니다.
세 명령이 모두 확인됐을 때만 led.sent=true입니다. 부분 전송 실패 시 이미 적용된 줄은 유지될 수 있습니다.
API led 응답에 top_emotions/top_colors/left_flow_period_ms를 추가합니다.
기존 RGBW 및 ROW,1 명령은 왼쪽 TOP 모드를 해제하므로 전체 소등도 계속 가능합니다.
현재 서버를 자동 재시작하거나 보드에 자동 업로드하지 않았습니다.

검증: ESP32 컴파일, 실제 감정 키 전체를 가진 입력의 순위와 0점 제외, 부족 순위 보완,
왼쪽 속도 우위, TOP→ROW2→ROW3 라우팅 및 오류 처리, 송신/ACK, 22개 범위 분리,
세 색의 공간 분포와 반복 이동, 다른 두 줄 유지, 출력 제한, 팔레트 전환 연속성, 개별/전체 소등.
검사는 가상 포트와 호스트 테스트이며 실제 발광은 업로드 후 확인해야 합니다.
